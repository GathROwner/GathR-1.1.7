# Earlier Hybrid callout tap delivery

Craig supplied a physical iPhone diagnostic trace from the opt-in capture. Hybrid received the release event at monotonic 74206104.981 ms, native selection at 74206458.316 ms and the shared handler at 74206458.404 ms: 353 ms elapsed before the handler. The prepared callout was cached, selection took 1 ms, and the first-frame proxy followed 365 ms later (719 ms from release-event receipt). Readiness, loading, programmatic-camera and processing guards were clear. Current's handler-to-selection was 14 ms and selection-to-frame proxy 262 ms, but its release callback was missing and its cluster had two venues versus Hybrid's sixteen. Do not treat Current's missing time as zero or attribute the entire render-time difference to Hybrid. No competing selection transition or race condition was demonstrated.

The patch targets the measured pre-handler interval. On iOS rich Hybrid markers, passive touch observers classify a completed stationary single-finger tap and immediately issue one public RNMapbox rendered-feature query against the existing point-annotation layer. Mapbox determines the painted hit, including summary pills and displaced annotations. This avoids waiting for annotation selection to enter the shared callout handler. Native selection remains the fallback for failed, missing, ambiguous and compact hits. A native callback arriving after the earlier delivery is suppressed within the existing 1,200 ms opening-guard interval. Native-only/accessibility activations do not acquire an indefinite latch.

No responder ownership, touch overlay, new native recognizer, native module, image/sizing change, cluster-tap sorting change, camera movement or continuous collision-layout pass is introduced. Pan, pinch, long press and cancellation do not start the earlier query. Pending results are rejected after another touch, camera/layout/map/mode changes, shared-gate rejection or annotation unmount. Absolute window layout must have been measured natively; relative fallback geometry is not used. Existing user-dot displacement, bitmap-refresh and gesture contracts remain covered.

The installed iOS RNMapbox binding assigns native UUIDs independently of React IDs. Its point manager is named `RNMBX-mapview-point-annotations`, and this app currently uses PointAnnotation only for Hybrid. A query's native point geometry is resolved to one committed registered annotation, with at most two world pixels allowed for native GeoJSON tile quantization. This tolerance resolves identity after Mapbox has already determined the hit; it does not expand hit bounds. Multiple matches or multiple painted targets retain the native path. Compact identities remain registered but use their existing source-press route. A pinned dependency-contract test checks the installed 10.3.0 binding's manager name, independent IDs and GeoJSON serialization. Mapbox's [11.18.2 point annotation source](https://raw.githubusercontent.com/mapbox/mapbox-maps-ios/v11.18.2/Sources/MapboxMaps/Annotations/Generated/PointAnnotation.swift) and [manager source](https://raw.githubusercontent.com/mapbox/mapbox-maps-ios/v11.18.2/Sources/MapboxMaps/Annotations/Generated/PointAnnotationManager.swift) support the native feature/manager contract; changing native annotation usage or upgrading the binding requires reviewing this mapping.
