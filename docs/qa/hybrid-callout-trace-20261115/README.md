# Separate Hybrid tap delivery from callout rendering

Craig confirmed no perceptible callout-opening improvement on iOS Production OTA `01a1dc2a` and a substantially faster Current map. He also confirmed that Hybrid's haptic arrives late. Haptics are requested near the beginning of the shared `handleMarkerPress`, so this narrows the next investigation toward pre-handler tap delivery. It does not prove a specific native SDK defect.

Current uses a React Native Touchable press. Hybrid uses Mapbox PointAnnotation selection. The installed RNMapbox iOS implementation routes the native single-tap recognizer through an asynchronous rendered-feature query before delivering annotation selection (`RNMBXMapView.swift`, `RNMBXPointAnnotationManager.handleTap`). Both app paths then enter the same callout preparation and selection function. No new Hybrid-only intentional delay was found inside that shared function. No physical iPhone timings have yet been collected; ADB inventory has no connected device.

This is measurement-only instrumentation. Passive map touch observers record a completed one-finger, low-motion release and associate it with the Current/Hybrid style and existing trace session. They never claim a responder, dispatch a cluster action, change a native recognizer, or prevent pan/pinch. Pinches, pans, long presses and cancellations are excluded from tap timing. Touch coordinates are transient local classifier inputs and are not added to the trace. Native selection receipt is recorded before annotation gating, including disabled/selected state. Existing handler, preparation, selection, mount, layout and first-JS-frame milestones remain available.

Release-to-handler timing begins when JavaScript receives the release event. Time already spent queued before that receipt is not included. A missing release callback remains missing rather than being estimated. Physical haptic delivery is asynchronous native work; Craig's delayed vibration is a useful lead, not proof by itself of where time is spent.

The existing Map Trace panel now shows release-to-handler, handler-to-selection, selection-to-frame and total times for recent openings. Missing measurements stay missing. Frame timing is a JavaScript animation-frame proxy, not proof of when pixels reach the iPhone display. A separate 32-entry opening-stage history survives eviction from the unchanged 160-entry camera/event log. Recording is dormant by default even in a diagnostic bundle. Start / Clear starts a capture and resets both histories; recording stops automatically after three minutes. Raw logs and summarized timings can be shared from the panel.

Visual evidence is `panel-fixture.png`: actual MapTracePanel through React Native Web with iOS props and explicitly synthetic fixture values. Independent image review confirmed readable measurements, hierarchy, spacing and actions. These values are not device results. Tests cover input classification, incomplete/mismatched/repeated opening attribution, bounded retention and export, plus the accepted Hybrid redraw/gesture/callout regression contracts.
